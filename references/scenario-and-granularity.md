# Scenarios and Granularity

## Select the Working Mode

### Field discovery

Use broad, nonexclusive coarse tags. The goal is a bird's-eye view of what exists, not a complete classification. Prefer titles, medium-frequency features, multiple sort orders, and a visible unclassified queue.

### Known problem or focused topic

Go directly to expressions tied to the problem. Search titles first, but expand to abstracts and keywords when title-only results are too sparse. Build `reference`, `priority`, and `uncertain` sets for study-design work.

### Compare candidate directions

Apply the same dimensions to each candidate: evidence volume, maturity, methods, unresolved problems, feasibility, required resources, and real-world value. Avoid selecting solely by publication count or journal prestige.

### Design or troubleshooting

Map methods, mechanisms, variables, failure modes, boundary conditions, measurements, and conflicting findings. Failed or anomalous results can define valuable branches.

### Writing

Use groups to build the paper or review structure. Search across opposing viewpoints and different periods or journals to reduce first-paper, prestige, and recency bias.

## Granularity Rules

- Use one coarse pass when a small collection already exposes actionable directions.
- Add a second pass when a target branch still mixes distinct research decisions.
- Add a third pass mainly for branches occupying a large share of the parent set, hiding useful expressions, or directly controlling the user's next action.
- Do not refine every branch symmetrically.
- Do not force group sizes below an arbitrary threshold.
- Stop when the user can formulate or compare a concrete next step.
- Return later if implementation shows that the map is too coarse.

Group names may be concise reminders. Store the exact query and scope separately when the label alone cannot preserve provenance.
